本 preset 的默认方向：Agent / LLM 应用工程师。重点考察能否把模型调用做成可验证、可恢复、有权限边界的应用，同时保留必要的 LLM 原理与编码考察。

能力地图：
- LLM 应用基础：结构化输出、工具调用、上下文预算、流式交互与模型选型。
- RAG：数据接入、切分、检索、混合检索、rerank、引用和端到端评估。
- Agent 执行：循环、状态机、规划、任务终止、工具错误、幂等、超时、重试与检查点。
- Memory 与上下文：短期状态、长期记忆、检索策略、失效、删除和隔离。
- 评估与观测：任务成功率、轨迹诊断、LLM judge 偏差、成本与延迟、回归和线上反馈。
- 系统设计：多租户、权限、人工确认、沙箱、prompt injection、并发与恢复。
- 项目表达：业务目标、本人贡献、基线、真实指标、故障复盘与可复现证据。

以下为本项目原创训练题，可直接使用；不是公司真题，也不是外部题库导入：
1. 用户问一个内部知识问题，Agent 答错了。如何区分数据、检索、上下文和生成问题？
2. 一个扣款工具执行超时后没有返回结果，Agent 应该重试吗？设计幂等键、状态查询和恢复路径。
3. 设计可取消、有步数与费用预算的 Agent 循环。哪些状态必须持久化？何时停止？
4. 检索召回率提高了，但最终回答准确率下降。提出三个可检验的假设与实验。
5. 如何建立 Agent 评估集？怎样同时度量最终任务结果、执行轨迹、安全边界和成本？
6. 在多租户长期记忆系统里如何处理租户隔离、过期信息、用户删除请求与检索污染？
7. 设计一个能够操作业务系统的客服 Agent，说明何时走确定性工作流、何时允许自主决策以及如何人工接管。
8. 你的多 Agent 方案比单 Agent 更贵却没有更好。如何定位问题，决定保留或合并哪些角色？

代码训练可使用“带超时、取消和最多三次重试的异步工具包装器”，要求用户说明哪些错误允许重试。项目深挖至少要求一个故障轨迹和一个可重复评估方案。
